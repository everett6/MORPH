# MORPH-Δ5B proposal: research reference audit

Audit date: 2026-10-19. Scope: cited research claims, requested bibliographic records, arithmetic, and the RTX 5070/Transformer Engine precision claim. Sources are papers, official project pages, or NVIDIA documentation/source. No claim here validates the proposed architecture or predicts its performance.

### Reference identification notes

- “TTT” is ambiguous in the proposal. The relevant model architecture appears to be Sun et al.'s *Learning to (Learn at Test Time): RNNs with Expressive Hidden States* (2024), rather than the broader 2020 test-time training method. Spell out the intended paper on first use.
- The proposal's use of LeanDojo-v2 “for trace extraction” is a reasonable match to its stated tooling. MiniF2F is mentioned elsewhere in relation to Goedel-Prover-V2, but should be named explicitly in the proposal's evaluation list if intended as a MORPH benchmark.

## RTX 5070 / Transformer Engine precision check

- NVIDIA identifies desktop GeForce RTX 5070 as a Blackwell GPU with 12 GB GDDR7. [NVIDIA RTX 5070 specifications](https://www.nvidia.com/en-us/geforce/graphics-cards/50-series/rtx-5070-family/). CUDA's official GPU table maps RTX 50-series devices to compute capability 12.0 (SM120). [CUDA GPU compute capability](https://developer.nvidia.com/cuda-gpus).
- Transformer Engine's official repository says FP8 is supported on Blackwell for both training and inference. More specifically, its live PyTorch source currently allows the standard FP8 support check at capability >=9.0 (which includes SM120); describes the HYBRID recipe as E4M3 forward and E5M2 backward; and selects Float8CurrentScaling as the default recipe on capability >=12.0. This supports a **software-declared FP8 training path** for SM120, not a guarantee that an arbitrary model or all kernels train correctly on a GeForce RTX 5070. [TE repository overview](https://github.com/NVIDIA/TransformerEngine), [TE quantization source](https://github.com/NVIDIA/TransformerEngine/blob/main/transformer_engine/pytorch/quantization.py).
- Format qualification matters. The current PyTorch source has `_compute_nvfp4_support`: `if get_device_compute_capability() >= (10, 0): return True`; **compute capability 12.0 satisfies this test**. The same source separately gates MXFP8 off at capability >=12.0. NVIDIA Transformer Engine 2.19 release notes explicitly say it added NVFP4 stochastic-rounding and RHT split-quantization support on SM120/SM121, and enabled row-scaled NVFP4 weight-gradient computation in dense `Linear` and `GroupedLinear` layers. This is evidence of partial NVFP4 training-path support on SM120, not a blanket assertion that every NVFP4 recipe/model path is supported. [TE 2.19 release notes](https://docs.nvidia.com/deeplearning/transformer-engine-releases/release-2.19/release_notes.html), [live TE source](https://raw.githubusercontent.com/NVIDIA/TransformerEngine/main/transformer_engine/pytorch/quantization.py).
- Therefore “SM120 FP8, partial NVFP4 training” is supportable if version-pinned and phrased precisely: standard FP8 check allows SM120 and the HYBRID recipe uses E4M3 forward/E5M2 backward; TE 2.19 documents specific NVFP4 operations added for SM120 including weight-gradient computation. This distinguishes training/backward support from inference-only quantization. It does not prove successful end-to-end MORPH training or numerical quality on an RTX 5070; exact-card validation remains unperformed in this research audit.
- The official repository's released overview and its live source can differ by version. The audit date above matters: pin the TE release/commit and CUDA version in any implementation recommendation. This audit intentionally does not install or run kernels.

## Suggested edits to the proposal's evidence wording

1. Replace “NVIDIA's current Transformer Engine matrix lists consumer Blackwell SM120 as supporting FP8, with partial NVFP4 training support” with: “Transformer Engine supports standard FP8 on SM120, and v2.19 release notes list specific NVFP4 training operations added on SM120; validate the selected recipes end to end on the exact RTX 5070 software stack before relying on them.”
2. Quote TNT's result as “up to 17× in the authors' tested setup,” with the baseline and experiment specified if a precise number is kept.
3. Label 373M/447M explicitly as estimated active-parameter counts from the proposed allocation. They do not yet establish a 13.4× training speedup: routing overhead, load balance, sparse gradient and optimizer semantics, recurrence, memory traffic, and kernel efficiency remain unmeasured.
4. The computed 694 TFLOP/s and 51.8 TFLOP/s are arithmetic lower bounds under 6ND, not RTX 5070 achievable throughput estimates. Keep that caveat adjacent to the numbers.
